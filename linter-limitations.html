Skill Linter Limitations

Known false positives, missing features, and structural limitations of the experimental skill linters used in CI. Maintained manually as signal accumulates.

skill-lint
Flags TypeScript files as TOXIC regardless of content
Any .ts file bundled with a skill is scored as a suspicious "bundled script", pushing the TOXIC score above the threshold (≥10) for skills that ship more than a handful of scripts. There is no allowlist or per-file exception mechanism — --help exposes only --json, --install, and --force-install.
  • Impact on this skill: 17 .ts scripts (survey, state management, workspace setup, etc.) are all flagged LOW, producing score 17 → verdict TOXIC.
  • Root cause: The linter's ToxicSkills ruleset treats compiled/script assets as inherently risky. More complex skills that ship their own tooling are penalized regardless of what the code does.
  • Workaround: None available. CI marks the job as non-blocking (continue-on-error: true).
skill-check
Security scan is built for MCP servers, not skills
skill-check delegates security scanning to mcp-scan (now snyk-agent-scan), which is designed to scan MCP server configurations (e.g. claude_desktop_config.json). When pointed at a skill directory — local path or GitHub URL — it finds no server config and returns target=(unknown target), causing skill-check to exit 1 with security: FAIL even when findings are 0. The FAIL is a category mismatch, not a discovered vulnerability. skill-check has been removed from CI in favour of gitleaks for secrets scanning.
agent-skills-lint
Does not recognise allowed-tools as a valid frontmatter key
@swarmclawai/agent-skills-lint warns on any frontmatter key it does not expect for the target flavor. The allowed-tools field is part of the Claude skill specification but is not in this linter's schema, so it generates a unknown-frontmatter-key warning on every skill that declares tool restrictions. The warning is a false positive — the field is intentional and valid.
agnix
Noisy on skill prompts that reference standard installation paths
agnix flags hardcoded user-specific directory paths (e.g. ~/.agents/skills/) as portability warnings even when they appear inside bash code blocks that are intentionally prescriptive about installation location. The warning is technically correct but produces noise for skills that document a canonical install path.
  • Affected files: prompts/triage.md:8, prompts/implement.md:33 — both reference OSL=~/.agents/skills/openspec-auto.
  • Status: The underlying portability concern is real (see GitHub issue). Until resolved at the script level, these warnings are expected.
No version-pinning detection for external tools
Emits an info-level message ("No tool or spec versions pinned") for any skill that references external CLI tools without locking versions. This is expected for skills that deliberately defer version selection to the runtime environment.
skillscan
Sentence length rule (QL-002) is poorly suited to technical skill documents
QL-002 flags any sentence over 30 words. Skills are instruction documents, not prose — they contain:
  • Mermaid diagram blocks counted as single run-on sentences
  • Markdown tables (multiple rows) counted as a single sentence
  • Dense technical instructions where splitting a sentence reduces precision rather than improving readability
The result is a high volume of QL-002 warnings, most of them false positives. The rule's 30-word cap was designed for marketing or documentation prose; it does not account for the structured, specification-style writing that effective skills require.
pulser
Relies on brittle section naming conventions
Pulser checks for the presence of specific section headings by exact name. For example, it requires ## Gotchas to satisfy the gotchas rule — a ## Red Flags section with identical content does not count. This is a naming convention match rather than a semantic check, so skills that use equivalent but differently-named sections are penalised with no actionable path other than renaming.
allowed-tools suggestion assumes analysis/research skills
When a skill is classified as generation, pulser auto-suggests restricting allowed-tools to Read, Grep, Glob. For orchestrator skills that need Bash, Agent, Skill, EnterWorktree, ExitWorktree, and ScheduleWakeup, this suggestion would break the skill entirely. The classification is also applied with low confidence (0.5) and does not account for mixed-type skills. Always derive the tool list from the skill's actual stage-by-stage behaviour rather than accepting the auto-fix.
agent-skill-linter
Package does not exist on npm
agent-skill-linter returns HTTP 404 from the npm registry. The job was removed from CI on 2026-06-17.
