Per-Tool Summary & Known Limitations

Tool Unique coverage Overlaps with False positives & known limitations Signal quality
quick_validate In CI Only tool that enforces the allowed frontmatter key list (rejects unknown keys). Authoritative Anthropic validator — maintained in the same repo as the skill spec. Schema checks (name, description, SKILL.md) shared with skill-check and agent-skills-lint None observed. Pinned to a specific commit SHA to ensure reproducible results across CI runs; no stable release tag is published. High
skill-lint Local only Sole security scanner. Covers all 10+ rule categories: prompt injection, obfuscation, RCE, credential exfil, external fetches, persistence tampering, destructive ops, metadata abuse, overbroad triggers, over-privilege, suspicious executables. Nothing else touches any of these. Nothing overlaps its security coverage. Rule R06 fires categorically on every .ts file regardless of content — every TypeScript script is scored as a suspicious “bundled executable.” 17 scripts → score 17 → verdict TOXIC. No allowlist or per-file exception exists; --help exposes only --json, --install, and --force-install.

R01–R05 and R07–R10 found nothing in actual content — the skill is clean. The TOXIC verdict is entirely from the file-type heuristic, not the content. Disabled in CI for this reason; kept in Justfile for local reference. 		High (unique category)
but unusable for skills with TypeScript tooling
agent-skills-lint In CI Supports 15+ agent flavors (Cursor, Codex, OpenCode, Aider, Gemini, Kiro, etc.) via flavor-specific schemas. Useful when validating cross-agent portability. All schema checks (name, description) covered by quick_validate and skill-check for Claude Code. Treats every .md file in the skill directory as a skill file. Prompt templates in prompts/*.md had no name: frontmatter → 6 false-positive errors. Fixed by adding YAML frontmatter to all prompt files.

allowed-tools not in schema. The allowed-tools field is part of the Claude skill specification but is not in this linter’s schema, so it emits an unknown-frontmatter-key warning on every skill that declares tool restrictions. The warning is a false positive — the field is intentional and valid. 		Low
skill-check Removed Deepest structural checker. Uniquely covers: name matches directory slug; file trailing newline; body line and token limits; local Markdown link resolution; references/ link resolution. Most configurable (plugin rules, allowlists). Highest community adoption at 69.7k downloads/month. Frontmatter schema overlaps quick_validate + agent-skills-lint. “Use when” trigger phrase overlaps pulser + cclint. Security scan is built for MCP servers, not skills. Delegates to mcp-scan (now snyk-agent-scan — a Snyk product), which is designed to scan MCP server configurations (claude_desktop_config.json). When pointed at a skill directory — local path or GitHub URL — it finds no server config and returns target=(unknown target), exits 1 with security: FAIL even when findings are 0. Category mismatch, not a real finding. Removed from CI; gitleaks used for secrets scanning instead. High (structural)
removed due to MCP scanner mismatch
pulser In CI Only tool checking allowed-tools frontmatter field. Produces a 0–100 score with structured prescriptions and skill classification (generation vs. analysis). Unique ## Gotchas section check (shared only with cclint). “Use when” trigger phrase overlaps skill-check + cclint. Gotchas check overlaps cclint. Brittle section naming. Checks section headings by exact string match — requires ## Gotchas, not ## Red Flags with identical content. No semantic equivalence; only fix is renaming.

Wrong allowed-tools auto-suggestion for orchestrators. When a skill is classified as generation (low-confidence 0.5), pulser auto-suggests restricting allowed-tools to Read, Grep, Glob. For orchestrators needing Bash, Agent, Skill, EnterWorktree, ExitWorktree, ScheduleWakeup, this would break the skill entirely. Derive the tool list from the skill’s actual behavior, not the auto-fix. 		Medium
cclint In CI Claude Code–specific quality scoring with a four-dimension breakdown (Structural / Practices / Composition / Documentation, 0–100). Checks for ## Anti-Patterns, ## Quick Reference, ## Workflow, ## Success Criteria sections. “Practices” dimension covers idiomatic Claude Code conventions not checked elsewhere. Supports circular dependency detection and baseline filtering. “Use when” trigger overlaps skill-check + pulser. ## Examples overlaps skillscan-lint. Gotchas/Anti-Patterns overlaps pulser. None observed. All findings at SUGGESTION level; scored 38/100 (D), a real signal about documentation completeness for a complex orchestrator skill. Medium
agnix In CI Only tool checking portability: hardcoded user directory paths, skill directory size limit, cross-platform shebangs, tool/spec version pinning. Supports multi-target validation (claude-code, cursor, codex, kiro) and SARIF output. 423 rules. Nothing else checks portability. Scans node_modules/ without excluding it. All 9 hardcoded-path warnings came from @types/node and typescript upstream packages, not our code. 8MB size error triggered by node_modules/ counted in directory size. Runs cleanly in CI (no node_modules/ installed), so CI passes; the local issue is a developer experience problem.

Flags prescriptive install paths as portability warnings. Paths like ~/.agents/skills/openspec-auto in intentionally prescriptive bash code blocks are flagged even when the prescriptiveness is the point. The underlying concern is real (tracked in a GitHub issue); until resolved at the script level, these warnings are expected.

Info-level “No tool or spec versions pinned” for skills that deliberately defer version selection to the runtime. Expected noise. 		Low (currently)
portability checks uniquely valuable in principle; node_modules false positives dominate locally
skillscan-lint In CI Only tool checking prose quality: sentence length, passive voice, superlatives, weasel words, nominalisations, acronym definitions. Also the most comprehensive documentation completeness checker: ## Inputs / ## Outputs, ## When to Use, ## Prerequisites, version:, tags:, changelog:. ## Examples check overlaps cclint. QL-002 sentence-length rule (max 30 words) does not understand Markdown structure. Tables, code blocks, and Mermaid diagrams are parsed as prose sentences — 18 of 18 QL-002 warnings were false positives: a table row counted as a 268-word “sentence,” a Mermaid diagram as a single run-on sentence. The 30-word cap is calibrated for marketing or documentation prose, not structured specification-style writing.

Prose-quality rules that fired on actual text content (superlatives, weasel words, acronyms) are real and actionable findings. 		Medium
prose rules poorly calibrated to agent skill documents; doc-completeness checks are real but opinionated

Coverage Gaps — Nothing Checks These

  • Content of TypeScript / JavaScript scripts beyond categorical file-type detection — no tool reads the actual logic, call graphs, or external dependencies of scripts/*.ts
  • Prompt template correctness — no tool checks that {{PLACEHOLDERS}} are consistent between the orchestrating skill and the templates it fills, or that templates are structurally complete
  • Inter-skill dependencies — no tool validates that skills referenced in SKILL.md (e.g. via superpowers:using-git-worktrees) actually exist in the installation
  • Runtime / behavioral testing — no tool invokes the skill against synthetic inputs to verify it behaves as documented
