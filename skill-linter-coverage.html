Per-Tool Summary

Tool Unique coverage Overlaps with False-positive problem Signal quality
quick_validate Only tool that enforces the allowed frontmatter key list (rejects unknown keys). Authoritative Anthropic validator. Schema checks (name, description, SKILL.md) shared with skill-check and agent-skills-lint None observed. High
skill-lint Sole security scanner. Covers all 10+ security rule categories: prompt injection, obfuscation, RCE, credential exfil, external fetches, persistence tampering, destructive ops, metadata abuse, overbroad triggers, over-privilege, suspicious executables. Nothing else touches any of these. Nothing overlaps its security coverage. R06 fires categorically on every .ts file, regardless of content. TOXIC verdict (score 17) is entirely driven by having a scripts/ directory with TypeScript. Rules R01–R05 and R07–R10 found nothing because the actual content is clean. High (unique category)
but noisy for skills with scripts
agent-skills-lint Supports 15+ agent flavors (Cursor, Codex, OpenCode, Aider, Gemini, Kiro, etc.) via flavor-specific schemas. Useful when validating cross-agent portability. All schema checks (name, description validation) fully covered by quick_validate and skill-check for Claude Code specifically. Treats every .md file in the skill directory as a skill file. Our prompts/*.md templates have no name: frontmatter → 6 false-positive errors. The tool does not understand the distinction between a SKILL.md and prompt template files. Low
skill-check Deepest structural checker. Uniquely covers: name matches directory slug; file trailing newline; body line and token limits; local Markdown link resolution; references/ link resolution. Also the most configurable (plugin rules, allowlists). Frontmatter schema overlaps quick_validate + agent-skills-lint. “Use when” trigger phrase overlaps pulser + cclint. None observed. High
pulser Only tool checking allowed-tools frontmatter field. Also checks skill classification (generation vs. analysis) and produces a score with structured prescriptions. Unique ## Gotchas section check (shared only with cclint). “Use when” trigger phrase overlaps skill-check + cclint. Gotchas check overlaps cclint. None observed. Medium
cclint Claude Code–specific quality scoring with a four-dimension breakdown (Structural / Practices / Composition / Documentation, 0–100). Checks for ## Anti-Patterns, ## Quick Reference, ## Workflow, ## Success Criteria sections. Unique “Practices” dimension covers idiomatic Claude Code skill conventions not checked elsewhere. Supports circular dependency detection and baseline filtering. “Use when” trigger overlaps skill-check + pulser. ## Examples check overlaps skillscan-lint. Gotchas/Anti-Patterns overlaps pulser. None observed. All findings were at SUGGESTION level (not errors or warnings); scored 38/100 (D), which is a meaningful signal about documentation completeness. Medium
agnix Only tool checking portability: hardcoded user directory paths, skill directory size limit, cross-platform shebangs, tool/spec version pinning. Supports multi-target validation (claude-code, cursor, codex, kiro) and SARIF output format. Nothing else checks portability. Scans node_modules/ without excluding it. All 9 hardcoded-path warnings were in @types/node and typescript upstream packages, not our code. The 8MB size error is triggered by node_modules/ being counted in the directory size. The portability checks themselves are genuinely unique and valuable — they just need node_modules/ excluded. Low (currently)
due to node_modules false positives;
checks are uniquely valuable in principle
skillscan-lint Only tool checking prose quality: sentence length, passive voice, superlatives, weasel words, nominalisations, acronym definitions. Also the most comprehensive documentation completeness checker: ## Inputs / ## Outputs, ## When to Use, ## Prerequisites, version:, tags:, changelog: — none of which any other tool checks. ## Examples check overlaps cclint. Sentence-length rule (QL-002) does not understand Markdown structure. Tables, code blocks, and Mermaid diagrams are parsed as prose sentences — 18 of 18 QL-002 warnings are false positives from these elements (e.g. a table row counted as a 268-word “sentence”). The prose-quality rules that fired on actual text content (superlatives, weasel words, acronyms) are real findings. Medium
prose rules poorly suited to agent
skill files; doc-completeness checks
are real but opinionated

Coverage Gaps — Nothing Checks These

  • Content of TypeScript / JavaScript scripts beyond categorical file-type detection — no tool reads the actual logic, call graphs, or external dependencies of scripts/*.ts
  • Prompt template correctness — no tool checks that {{PLACEHOLDERS}} are consistent between the orchestrating skill and the templates it fills, or that templates are structurally complete
  • Inter-skill dependencies — no tool validates that skills referenced in SKILL.md (e.g. via superpowers:using-git-worktrees) actually exist in the installation
  • Runtime / behavioral testing — no tool invokes the skill against synthetic inputs to verify it behaves as documented
